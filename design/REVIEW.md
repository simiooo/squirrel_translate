# Squirrel UI v2 — 设计验收稿

状态：用户于 2026-10-21 批准开始改造，v2.1 方向已落地到 Go / mygo 实现。`.fig` 与 JSX 保留为评审稿；实现同时遵循后续的“短语分类、星星收藏、移除笔记编辑入口”要求。新测试版为 `dist/squirrel-translate-v2.exe`。

实现包含共用设计 token、浅深色、无边框主窗口、侧栏导航、并排翻译工作台、词汇列表与详情、四组设置及窄窗口布局。主窗口关闭隐藏至托盘，收藏和流式请求沿用既有业务层。实际截图在 `artifacts/ui-v2/previews/`。

验证包含 headless 交互与截图、独立隐藏 Windows 窗口中的流式替换/取消、顶部缩放命中。拖动跨屏、Win+方向键、混合 DPI 与不同 Windows 版本的最终视觉效果仍需实机人工覆盖，静态截图不作为这些行为的通过证据。

## 在 OpenPencil 中评审

打开新版 `design/squirrel-v2-1.fig`。`design/squirrel-v2.fig` 保留为第一版对照。画板顺序：

1. Floating translation：划词工具条、精简单词、句子、深色和等待状态。
2. Translation workspace：主窗口的输入与译文双栏。
3. Vocabulary：列表 / 详情、收藏与笔记。
4. Model settings：接口、模型、凭据与生成参数。
5. Translation settings：语言、划词、上下文和排除应用。
6. Resilience and states：长文、错误、置顶与深色。
7. Foundation & components：字体、色彩、间距、ghost 按钮四种状态和复选项。
8. Color and interaction states：浅深色导航状态、普通/主要/危险操作状态矩阵与对齐规则。

`.fig` 是可编辑设计图层；同目录 JSX 是生成源，`tokens.json` 是基础变量，`previews/*-v21.png` 是第二轮通过 OpenPencil 自带场景图与渲染器离线导出的验收图。这些是设计稿，不是已接通业务的交互原型。第二轮实时画布遇到 CanvasKit 内部错误，因此使用离线引擎保存新版，不依赖当前不稳定的编辑器标签页。

## 设计方向

采用 Windows 桌面工具的阅读密度，而非营销页的超大标题与卡片堆叠。外围柔和浅灰，阅读区域白色；深色采用有层次的中性灰。正文使用深色，辅助文字保持足够对比。普通操作使用中性灰，蓝色用于主要操作和选择状态；绿色表达成功，红色用于危险操作。状态不能仅靠颜色表达。

- 中文：Microsoft YaHei UI，Regular / Bold。避免请求本机不存在的 Medium / Semibold 字面。
- 拉丁文字：Segoe UI Variable Text，Regular / Semibold。
- 字阶：12 辅助、13 控件标签、14 常规 UI、16–20 阅读正文、24 页面标题、28 单词。
- 网格：4 DIP 为基准；相关信息 4–8，组内 12–16，跨区 24–32。主内容左右 28，浮窗正文左右 16；单词释义紧密成组。
- 主窗口基准 1040 × 704；左导航 164；设置标签列 104，标签到输入 16。
- 标准按钮点击高度 32；默认透明，hover 轻量背景，focus 覆盖描边；文字和容器尺寸始终不动。
- 窗口圆角 12；按钮、菜单选中与列表项圆角 8；14px 复选框圆角 4；3px 选中标记圆角 2。常态按钮没有描边或实体底色。内部内容由排版组织，不嵌套卡片。
- 图标统一 18 / 1.65 线宽；图标源为本地矢量路径，不依赖网络图片或 emoji。

色彩、字号、间距及圆角已建为 OpenPencil 变量。SVG 图标暂使用同源 token 值，后续实现应全部读取主题；组件画板提供原生 Component 身份，页面排版使用 auto-layout。此稿不宣称已经完成全部组件实例化或响应式运行逻辑。

## 第二轮颜色与状态规则

| 语义 | 浅色 | 深色 | 使用位置 |
|---|---|---|---|
| 侧栏底色 | `#F4F5F7` | `#171A20` | 导航所在的底层表面 |
| 普通 hover | `#ECEEF2` | `#30353E` | 复制、刷新、关闭、未选菜单 |
| 普通 pressed | `#E1E5EB` | `#3A414C` | 按下时，保持同一几何尺寸 |
| 选中背景 | `#DCE7FC` | `#334B77` | 当前菜单、当前词汇、置顶 |
| 选中 hover | `#CFDDF8` | `#3E5888` | 已选中元素的悬停 |
| 选中文字 | `#234A9C` | `#E0EAFF` | 加粗，配合 3px 状态条 |
| 主操作文字 | `#315ECA` | `#9ABBFF` | 翻译、保存、重试 |
| 主操作 hover / pressed | `#EAF0FC` / `#DBE6FA` | `#2A3852` / `#35486B` | 轻量着色反馈 |
| 成功文字 | `#237A57` | `#8ED5B3` | 连接正常、已收藏，搭配勾号 |
| 危险文字 | `#AA3542` | `#FFADB8` | 移除，仍需明确文字语义 |
| 危险 hover / pressed | `#FBEDEF` / `#F4D9DE` | `#482A31` / `#59333D` | 危险操作反馈 |
| Focus | `#315ECA` | `#9ABBFF` | 2px 覆盖描边，不参与布局 |

选中不能只依赖底色：侧栏及词汇列表均加入 3px 状态条，同时改变文字字重。普通 hover 使用中性色，选中背景使用更明确的蓝灰色；选中 + hover 使用独立 token。focus 可以叠加在任意状态上，不等同于 selected。disabled 禁止响应 hover / pressed，保留尺寸并降低整体不透明度。

各状态共享圆角，禁止 hover 突然变胶囊、focus 突然直角。8px 圆角对应 32px 按钮或 40px 导航项；容器圆角 12，不把所有元素统一成同一个半径。选中状态条宽 3、高 20、圆角 2，不触碰外围圆角。

浮窗标题、正文首字、底部左侧操作图标的布局边界统一为 x = 16。标题直接使用这条布局线；正文不再通过内容宽度推导对齐。底部点击区从 x = 8 开始，内部保留 8px，图标落在 x = 16。图标+文字按钮的文字自然跟随图标，不能通过删除按钮内距来追求文字对齐。字形本身的边距与逻辑边界分开检查。

## 无边框窗口规范

全应用隐藏系统标题条和可见系统边框，保留圆角与柔和投影。主窗口自绘 44 DIP 顶栏，保留最小化 / 最大化还原 / 关闭，遵循 Windows 右侧顺序。顶栏空白可拖动；控件、选择器和文本交互区域排除拖动命中。

实现验收时必须覆盖：

- 主窗口 8 DIP 隐形缩放边缘、角点命中、拖动、双击顶栏最大化 / 还原、系统菜单、Alt+F4 和 Win+方向键。
- 最大化时取消窗口外圆角 / 投影空隙，内容不被任务栏遮挡；DPI 切换和负坐标显示器布局正确。
- 主窗口关闭进入托盘；托盘提供退出。首次关闭的行为反馈采用一次性提示，不常驻界面。
- 浮窗按内容确定初始高度，短内容不留大块空白；最大尺寸受显示器工作区限制，建议上限 640 × 720，最小宽 360。
- 浮窗只让正文滚动，标题与操作固定。滚动条仅在溢出时出现；用户回看时停止自动跟随流。
- 非置顶浮窗失焦关闭并取消请求；语言菜单属于本窗口交互，不能因打开菜单误关闭。置顶窗口各自保持选文快照。
- 划词工具条不抢源应用焦点，全部浮层进行碰撞检测。

这些行为将在设计验收后的实现阶段验证；静态稿不代表已实现原生窗口能力。

## 内容与状态

单词保留精简策略：有上下文一项最佳释义，无上下文最多三项；不恢复发音、例句、词形等额外生成。正文开始前用单行思考作为临时等待状态，每 100ms 合并；正文开始后隐藏，不加入常驻折叠面板。刷新保留在标题旁，目标语言无箭头。

长文不扩大到工作区以外；错误给出简洁原因与恢复入口。按后续用户要求，收藏使用空心 / 实心星星；复制反馈短暂替换原标签，不增加新行。输入焦点使用覆盖绘制，无内距、边框占位或位置变化。

设置页按模型 / 翻译 / 快捷键 / 外观分组。高级参数作为原位展开区域；常用参数先显示。此稿展示两个主要设置分组，快捷键与外观细节在方向确认后沿同一结构完善。

窄窗口方案：宽度低于 880 时主导航收成图标栏；翻译双栏在内容区小于 600 时上下排列；词汇详情改为单页并提供返回。此轮提供桌面基准尺寸，窄窗口方案尚未逐尺寸绘制。

## 参考依据

- [Fluent 2 Typography](https://fluent2.microsoft.design/typography)：Windows 字体与明确的字号层级。
- [Fluent 2 Layout](https://fluent2.microsoft.design/layout)：以 4px 网格表达内容关系。
- [Microsoft 标题栏定制](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar)：定制标题栏同时保留拖动和窗口控制。
- [OpenPencil MCP](https://openpencil.dev/programmable/mcp-server)：可编辑图层与本地文件工作流。

这是基于当前成熟桌面规范的 2026 年设计提案，不把“年度流行风格”当成统一标准。原生 mygo 是否足够承载效果，会在设计确认后以文字渲染、输入体验、窗口行为做技术验证，再决定 UI 层是否替换；Go 业务与平台能力继续保留。
